## SocialSimuLLM 研究平台更新方案

**核心理念：** 以个人研究者为中心，聚焦“高认知精度的社会涌现”研究，通过融入最前沿的AI驱动技术，将项目从单体仿真框架，演进为一个**轻量、可扩展、以自然语言驱动的计算社会科学实验平台**。

---

### 一、 目标与原则

#### 1.1 核心目标

- **研究驱动，而非平台驱动**：一切更新服务于产出有价值的研究洞察（社会涌现、群体决策、信息传播等）。
- **低成本、高能力**：通过统一接口调用云端大模型API（如DeepSeek），摆脱对本地小模型的依赖，获取最佳性能与速度。
- **自然语言驱动实验**：构建“你描述世界，AI生成世界”的实验范式，大幅降低环境搭建成本，并利用多样性环境测试理论的鲁棒性。
- **前沿认知架构**：引入层次化记忆（Hindsight/ARTEM）、递归决策框架（ROMA）等最新技术，让Agent的“心智”更贴近真实人类。
- **标准与开放生态**：通过集成MCP、A2A等协议，使平台具备与外部工具、数据源乃至其他仿真系统互联互通的能力。

#### 1.2 设计原则

- **渐进式重构**：以最小可行产品（MVP）驱动，分阶段实施，每阶段都可产生一个可运行、可产出研究成果的版本。
- **模块化与可替换**：核心引擎、认知模块、环境生成器等均以接口隔离，方便实验不同的算法或框架。
- **可复现与科学严谨**：所有实验（尤其是AI生成环境）都必须记录模型版本、参数、随机种子，确保结果可追溯。

---

### 二、 整体架构演进蓝图

我们将从当前的单体架构，逐步向“微内核+插件化”的架构演进。

**[当前架构]**
`主循环调度器` → (感知 | 规划 | 行动 | 记忆/反思)
均在主循环内顺序调用。

**[目标架构]**
```
┌──────────────────────────────────────────────┐
│                 实验导演模块                   │
│  (自然语言 --> 场景配置、变量控制、运行与监控)    │
└──────────────────────────────────────────────┘
                        │
┌───────────────────────┼───────────────────────┐
│            仿真核心 (微内核)                   │
│  时间推进 │ Agent生命周期 │ 事件总线 │ 空间图管理 │
└───────────────────────┼───────────────────────┘
          ┌─────────────┼─────────────┐
          │             │             │
 ┌───────┴───────┐ ┌───┴───┐ ┌───────┴───────┐
 │ 认知插件总线  │ │ 环境  │ │ 标准化接口层   │
 │ - 记忆系统    │ │ 生成器 │ │ MCP │ A2A     │
 │ - 决策引擎    │ │ (AI驱动) │ │ LiteLLM    │
 │ - 人格模型    │ │        │ │ 外部数据    │
 └───────────────┘ └───────┘ └───────────────┘
```

**关键点：**

- **仿真核心**极小且稳定，只负责时间推进、事件分发。
- **认知能力**（记忆、规划、反思、人格）均以插件形式挂载，可独立升级。
- **环境生成器**独立模块，支持手动定义与AI自动生成两种模式。
- **标准化接口层**使得Agent可以调用外部工具，或与其他Agent系统交互。

### 三、 分阶段实施计划

根据个人开发者的时间与精力，建议划分为三个主要阶段，每个阶段都可产生研究产出。

#### 3.1 第一阶段：认知内核升级与AI环境生成尝鲜（1-2个月）

**目标**：在不改动现有主循环的前提下，将最具价值的“记忆系统”和“世界生成”能力以最小成本融入，快速产出研究结果。

##### 3.1.1 引入LiteLLM统一模型调用

- **行动**：
  - 创建一个 `LLMClient` 类，封装LiteLLM调用。
  - 替换所有直接的OpenAI调用，统一支持 `deepseek-chat`、`qwen-plus` 等多种模型。
  - 实现一个简单的成本统计与模型切换功能。
- **收益**：即刻获得最佳性价比的模型能力，实验成本可控。

##### 3.1.2 记忆系统升级：引入“结构化时间线 & 时空情景记忆”

借鉴Hindsight和REMEM的思路，将现有记忆拆分为三层：

- **行动**：
  - **保持工作记忆**：当前视野内的事件。
  - **重构情景记忆**：不再是一堆向量，而是 `(时间戳, 地点ID, 事件类型, 实体, 描述, 重要性)` 结构化条目，存入数据库（如LanceDB或轻量SQLite+向量扩展）。
  - **实现时空回忆API**：
    - `recall_time_span(start, end)` 按时间线检索。
    - `recall_location(loc_id)` 检索与特定地点相关的所有记忆。
    - `recall_semantic(query)` 保留原有语义检索。
  - **改造反思模块**：反思时，同时调入时间线事件和语义相关事件，生成更连贯的个人叙事。
- **新实验**：立即可以进行“**基于地点记忆的社会习惯形成**”实验，观察 Agent 是否会因为过去在某地发生的好事而对该地产生偏好。

##### 3.1.3 AI世界生成初步集成

- **行动**：
  - 编写 `WorldVariationGenerator` 工具脚本。
  - 输入你现有的空间图描述（JSON），调用云端模型生成3-5个逻辑变体（如“增加一个公园”“改变道路连接”）。
  - 手动验证后，把这几个变体作为配置文件保存。
- **收益**：你立刻获得了多个实验环境，可以用来测试同一组Agent在不同空间结构下的行为差异，产出“**空间结构对社会交互模式的影响**”这样的研究。

**第一阶段产出预期：**
- 一篇工作论文或博客，主题为“**空间情景记忆对社会习惯形成的影响**”或“**记忆增强型LLM Agent在谣言传播中的自我纠偏能力**”。
- 系统已支持多模型切换，实验成本清晰可控。

#### 3.2 第二阶段：决策架构升级与标准化接口（3-6个月）

**目标**：重构核心行为调度，引入基于递归分解的决策框架，并通过MCP/A2A协议打开系统边界。

##### 3.2.1 引入ROMA式递归任务分解

- **行动**：
  - 将原有的线性“日计划-小时计划”替换为一个 `MetaController`。
  - **思想**：遇到复杂目标（如“组织一场生日派对”）时，`MetaController` 会生成一个子任务树（“邀请朋友”->“确定名单”->“逐个邀请”），并递归调度。
  - 这需要将Agent的内部行为建模为类似“堆栈”的结构。
- **收益**：Agent能处理长期的、多步骤的复杂社会协调任务，而不仅仅是简单的日常循环。

##### 3.2.2 空间感知与移动决策升级

- **行动**：
  - 将空间表示为基于图的 `NetworkX` 结构（节点=地点，边=路径）。
  - 实现 `PathPlanner`，结合LLM规划与A*算法：LLM根据“目标+记忆中的偏好”提供一个高层路径意图（“先去咖啡店，再去书店”），底层由A*计算最短路径。
  - 引入 `FieldOfView`：根据Agent当前位置，生成文本化的“周围环境描述”，作为感知输入。
- **收益**：空间不再是离散格子，而是一个有实际拓扑意义的网络，移动决策更具可解释性。

##### 3.2.3 集成MCP和A2A协议原型

- **行动**：
  - **实现A2A基础能力**：允许两个Agent以标准化的消息格式进行对话，并包含意图、上下文。这将替换现有的简单`chat`模块。
  - **实现MCP客户端**：让你的Agent有能力通过MCP调用一个外部工具（示例：一个简单的“天气查询”工具或“维基百科搜索”工具）。
  - 设计时注意，工具调用也通过 `LiteLLM` 的统一 `tool_call` 接口实现。
- **收益**：系统不再是封闭沙盒，Agent可以获取真实世界信息，或与其他遵循同样标准的仿真框架互通。

##### 3.2.4 实验工具箱构建

- **行动**：
  - 构建独立的 `ExperimentRunner` 类，用于：
    - 定义Agent组、环境配置、实验参数。
    - 自动运行多个副本（带不同随机种子）。
    - 收集所有Agent的状态日志、对话、决策理由，并导出为Pandas DataFrame。
  - 编写一组基础的Jupyter Notebook分析模板。
- **收益**：你可以像写实验报告一样定义仿真，然后静待结果输出统计图表，极大提高研究效率。

**第二阶段产出预期：**
- 系统已具备处理复杂长期任务的能力，可进行“**多步协调任务的涌现与失败模式**”研究。
- 标准化的实验流程，让研究变得系统、可复现。
- 一篇关于“**递归分解规划在LLM Agent社会协作中的作用**”的论文初步。

#### 3.3 第三阶段：AI原生世界生成与开放式演化（6个月以上）

**目标**：最终实现“用自然语言描述实验，AI生成世界并运行动态仿真”，并探索开放式的社会共同演化。

##### 3.3.1 实现“零代码场景构建”

- **行动**：
  - 构建 `NLScenarioParser`：输入一段自然语言描述，利用LLM输出一份标准化的场景JSON（包含空间图、Agent列表、初始社会网络、事件时间线等）。
  - 结合第二阶段的环境生成器，将此JSON直接加载运行。
  - 系统进入正式运行前，显示生成结果并请求确认。
- **收益**：真正的“自然语言驱动仿真”，你只要提出一个假设（例如，“在一个高信任度社区和低信任度社区中，谣言传播有何差异？”），AI就为你搭建两个世界并运行实验。

##### 3.3.2 开放式共同演化探索

- **行动**：
  - 引入简单的“选择性压力”与“变异”机制，但非基因层面，而是**文化演化**。
  - 允许Agent在交互中修改自己的部分“人格参数”或“社会规则”（如合作倾向），或生成新的行为策略，并受社会环境选择。
  - 这其实已接近SOCIETY ZERO UNIVERSE的思路。
- **收益**：研究社会规范、合作、语言等如何从简单交互中涌现，是计算社会科学皇冠上的明珠。

##### 3.3.3 构建完整的AI研究助手回路

- **行动**：
  - 结合YuLan-OneSim的思想，让你的“实验导演模块”进化为一个AI助理：
    - 你：“研究‘信息茧房’效应。”
    - 系统：自动设计实验（隔离vs混合网络），生成世界，运行，分析结果（包括p值），撰写报告初稿。
    - 你仅需审阅和引导。
- **收益**：个人研究者的生产力放大到极致，你更像一个“首席科学家”，而不是程序员。

### 五、 实验设计与研究议题建议

为让更新直接服务于研究，以下是一些可直接落地的实验菜单：

1.  **记忆对空间使用的影响**
    - **变量**：有/无空间情景记忆。
    - **环境**：同一个空间图。
    - **观察**：有记忆Agent是否会发展出“领地行为”或“习惯路径”，而无记忆Agent则完全随机游走。
2.  **网络结构对群体纠偏能力的影响**
    - **变量**：全连接 vs. 小世界 vs. 无标度信息传递网络。
    - **任务**：注入一条谣言。
    - **观察**：哪种网络能以最快速度达到群体共识，澄清谣言？反思（核实）机制在哪种网络中效用最大？
3.  **AI生成环境的多样性测试**
    - **方法**：用 `WorldVariationGenerator` 生成10个不同的小社会。
    - **固定研究问题**：检验“高密度居住区是否会增加冲突频率”这一假设。
    - **观察**：该规律在所有AI生成的变体中是否普遍成立？如果不，是哪一类环境的特征破坏了它？这本身就是重大发现。
4.  **多步任务协作中的涌现领导力**
    - **任务**：一组Agent需要合作将一块虚拟巨石从A点移到B点（需要一个共同的说话人、几个执行者）。
    - **观察**：具备 ROMA 式递归规划的Agent，是否能自发地产生临时领导角色，并制定出有效的分步计划？

### 六、 风险与应对

| 风险                                 | 应对策略                                                     |
| :----------------------------------- | :----------------------------------------------------------- |
| **API调用成本失控**                  | 严格设定单次实验预算上限；对简单对话使用缓存（如自定义记忆精确命中时直接返回历史回复）；优先使用免费或极度廉价的模型（如MiniMax-M2的免费额度）。 |
| **AI生成世界逻辑混乱**               | 建立一套自动校验规则（如“所有Agent初始位置必须在定义的节点上”）；在生成后要求LLM自我修正；初期人工审核。 |
| **新架构引入的复杂性压倒个人开发者** | 严格遵循“插件化”思想，每次只替换一个模块，保持整体始终可运行。不追求一步到位的完美架构。 |
| **实验结果难以复现**                 | 建立严格的实验日志，包含模型+版本、全部提示词、随机种子、环境快照。建议使用MLflow等工具进行轻量级实验追踪。 |
| **个人时间精力有限**                 | 以研究问题驱动更新，而不是为了技术而更新。如果某个更新不能直接帮助你回答一个有趣的研究问题，就大胆推迟。 |
