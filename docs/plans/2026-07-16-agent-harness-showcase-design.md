# Agent / Harness 展示设计

## 背景与目标

现有“研究档案”展示保留完整的项目总览、技术路线、系统验证、实验设计和结果分析，继续作为完整版本保留。新增一套“Agent / Harness”视图，服务于更短的技术讲解：先说明 Agent 如何被结构化约束、如何协作，再说明实验中的 Prompt、事件、人设与环境如何配置，最后用论文小镇和校园归档给出结果证据。

新视图不复制旧档案的长篇叙事，也不启动模型。所有证据来自当前代码路径、只读 ResearchCase 和论文四人小镇归纳记录。

## 信息架构

侧边栏新增独立视图“Agent / Harness”，包含五个入口：

1. **Agent 总览**：一屏说明“感知 → 召回 → 规划 → 行动 → 写回 → 反思”，并给出讲解顺序。
2. **Harness 设计**：展示结构化 Action、MemoryEntry、ReflectionEngine、状态与输出校验，以及失败时的 fallback / cooldown。
3. **协作协议**：展示 FOV、InteractionCoordinator、PathPlanner 和 Memory 路由如何限制 Agent 之间的可见性、对话、移动和信息传播。
4. **Prompt 实验**：将人设、环境、事件注入、时间窗口和分支继承分层，提供一个只读分支选择器。
5. **结果证据**：用论文四人小镇行为趋势和校园 GE / NA 描述性编码做紧凑证据卡，不展开完整社会科学分析。

旧“研究档案”视图的页面和数字不删除、不复用为新视图的主导航；两套入口通过数据来源说明明确区分。

## Harness 设计重点

Harness 页按“输入契约—执行循环—输出契约”组织。输入包括 Agent 身份、世界可见范围、当前目标、事件和召回记忆；执行循环由 SimulatorCore 以 10 分钟为步长推进，按边界触发日计划、时计划、行动、移动、印象、反思和检查点；输出包括 `AgentAction`、`MemoryEntry`、结构化日志和持久化状态。

校验卡片明确四类稳定性：枚举/字段校验、状态写回、协作边界、触发节流。不要宣称 LLM 输出“正确”，而是展示系统如何把不稳定的自然语言压缩为可验证的结构，并在失败时使用 fallback、跳过无效反思或记录边界。

## Prompt 实验重点

Prompt 页展示三层输入：

- 人设：姓名、背景、偏好、关系与目标；
- 环境：地点描述、可见 Agent、空间图与路径约束；
- 事件：全局/定时事件、接收对象、开始时间、持续时间和方向。

分支卡片只读显示继承关系和介入参数，说明研究者改变的是实验条件，不是直接替 Agent 做行动。校园 case 的 GE / NA 结果只作为结果证据入口，不在 Prompt 页重复所有分析。

## 验证与边界

- Harness 证据：单元测试、代码路径和结构化数据契约；不等于模型质量基准。
- 小镇证据：论文中的四人、四地点、约 78 轮行为趋势归纳；不等于重新运行结果。
- 校园证据：GE / NA 两组各 4,200 条主行动的描述性编码；不等于采纳率或因果效应。
- 新页面必须在无 API key、无模型调用和无本地旧 t7 快照时正常加载。

## 验收

1. 旧“研究档案”入口仍能打开，导航和页面不被新入口改变。
2. “Agent / Harness”默认进入 Harness 设计页，首屏可在 2 分钟内讲清核心闭环。
3. Harness、协作、Prompt、证据四页均有代码/数据来源路径。
4. Streamlit AppTest 无异常；页面纯函数测试覆盖核心卡片和分支适配。
