# 3.1.0 开发报告

> 日期：2026-07-16
> 分支：`dev-3.1.0`
> 当前提交：`b5defe4`
> 对比基线：`Release-v3.1.0`（`93969ba`）

## 0. 交付结论

3.1.0 已完成从原型式单体仿真到可配置、可追踪、可分析研究平台的主要升级。交付覆盖仿真核心拆分、结构化记忆与反思、实验运行与检查点、空间与规划能力、Streamlit 结果分析，以及离线研究展示和 Agent / Harness-first 展示。当前代码通过编译检查与默认离线测试门禁；3.1.0 仍保留明确边界：文化演化、LiteLLM 全量集成和 A2A/MCP 原型暂缓，在线 LLM 的模型质量与成本不属于本次离线验证结论。

本次分支相对 `Release-v3.1.0` 共包含 31 个提交，涉及 213 个文件，新增 26,410 行、删除 1,984 行。

## 1. 交付物

### 1.1 仿真核心与认知能力

- [x] 将原有主程序拆分为 `SimulatorCore`、`SimulationState`、`EventBus` 等模块，主入口负责 CLI 分发。
- [x] 将 Agent 的记忆、移动和行为逻辑收敛为类方法，移除 `MethodType` 绑定模式。
- [x] 以冻结的 `MemoryEntry` 作为统一记忆记录，支持类型化字段、兼容旧数据和组合检索。
- [x] 实现 `ReflectionEngine`，支持日常、模式和社交反思，并通过日末/重要性阈值触发。
- [x] 加入反思冷却、最近动作记录、邻近 Agent 感知和动作内嵌对话，降低重复行为并提升交互可追踪性。
- [x] 加入时间范围事件、事件生命周期刷新和兼容旧事件字段的读取逻辑。
- [x] 将主要仿真 LLM 调用迁移到结构化 JSON 输出，提供 Markdown 代码围栏解析、重试和文本回退。

### 1.2 实验基础设施与研究分析

- [x] 增加基于 Pydantic 的 `ExperimentConfig`，支持 YAML 序列化和运行时配置桥接。
- [x] 增加 `ExperimentRunner`，支持单次运行、批量运行、种子配置和实验目录管理。
- [x] 增加 JSONL 结构化日志、检查点保存/加载、可恢复运行和模型调用元数据记录。
- [x] 增加实验存储、结果汇总、DataFrame 加载、跨实验比较和 Jupyter 分析模板。
- [x] 增加 A/B 测试配置，覆盖反思、视野、路径规划、目标规划和空间拓扑。

### 1.3 空间能力与前端

- [x] 增加 `WorldVariationGenerator`，支持 ring、small-world、grid、random 和 scale-free 拓扑。
- [x] 增加基于图距离的 `FieldOfView`、LLM 移动意图识别、A* 最短路径和多跳移动。
- [x] 增加目标驱动的层次化规划和递归任务分解。
- [x] Streamlit 支持配置实验、查看结果、检查点回放、空间/活动/迁移热力图和研究助手。

### 1.4 离线展示与证据链

- [x] 新增无需 API 调用的离线演示快照、展示数据适配器和研究案例加载器。
- [x] 保留原有研究档案入口，并新增论文研究展示、校园案例展示和 t7 系统验证展示。
- [x] 新增 Agent / Harness-first 独立入口，按 Agent 总览、Harness 设计、协作协议、Prompt 实验和结果证据组织。
- [x] 展示中明确区分代码/结构化契约证据、离线案例证据与真实模型实验结论，避免将展示快照表述为实时重跑结果。

## 2. 关键架构决策

| 决策 | 说明 |
| --- | --- |
| 以 `SimulatorCore` 作为调度边界 | 保留 10 分钟步进和既有行为顺序，将日计划、小时计划、行动、移动、印象、反思、事件和检查点集中在明确的生命周期中。 |
| 以 `MemoryEntry` 作为统一数据契约 | 让记忆存储、反思、日志、检查点和分析共享同一组类型化字段，降低模块间的隐式转换。 |
| 结构化输出优先，回退路径保底 | 用 JSON schema 和预设 fallback 收敛 LLM 输出；解析失败时保留原始文本，避免静默丢失模型结果。 |
| 核心仿真与展示数据解耦 | 真实实验仍走 `ExperimentRunner`；离线展示读取只读 manifest/checkpoint，不在页面加载时调用模型，保证演示稳定。 |
| 保留旧研究档案，新增 Agent / Harness 入口 | 旧展示提供完整研究背景，新入口突出结构化 Agent、协作边界、Prompt 条件和证据，满足不同讲解时长。 |
| 采用“可配置复现”而非“模型结果完全一致”表述 | seed、YAML、日志和检查点保证运行过程可追踪；真实结果仍受模型版本、服务端行为和外部 API 影响。 |

## 4. 已知限制与后续事项

- F-308 轻量文化演化、F-309 LiteLLM 全量集成、F-312 A2A/MCP 原型在 PRD 中明确为 Deferred，不作为 3.1.0 的完成项。
- 默认测试覆盖离线代码路径和结构化数据契约，不覆盖真实 API 的延迟、费用、限流、模型差异和长时运行稳定性。
- 离线展示使用维护好的案例 manifest、检查点和描述性编码；它用于讲解和证据索引，不等同于现场重新运行实验，也不直接推出因果结论。
- 实验配置已具备较完整的模型、空间、记忆、反思和运行参数，但部分高级能力仍依赖对应开关、可选依赖和有效的 LLM 配置。

## 5. 升级与迁移说明

- 使用新 CLI 和实验模式时，建议从 `examples/` 中的 YAML 配置开始，并通过环境变量提供 API 凭据；不要把密钥写入配置文件或提交到仓库。
- 新运行结果默认保存在实验运行目录中，包含配置、JSONL 事件日志、检查点和分析所需的结构化数据。
- 旧的项目数据仍可作为参考或通过兼容加载路径读取；新实验应优先使用 `MemoryEntry`、`ExperimentConfig` 和当前运行目录契约。
- 启用 DeepSeek V4 JSON 模式时可使用结构化输出；遇到服务端不支持或解析异常时，系统会按重试与 fallback 路径继续记录可用文本。
- 前端展示建议使用离线案例验证页面流程，再显式启动真实实验；无 API key 时，Agent / Harness 和研究案例展示仍应保持可加载。
